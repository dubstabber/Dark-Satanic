# Dark Satanic — working conventions

Godot 4.7.1, GDScript, GUT 9.7.1. Run `tools/run_tests.sh` before every commit; `tools/check_script_sizes.sh`
must pass.

## Architecture rules
- One responsibility per script. Target < 200 lines, ceiling 300 — `tools/check_script_sizes.sh` prints a
  NOTE above 300 (split the script when you next touch it); its hard gates (WARN > 700, FAIL > 900) and
  `gdlintrc`'s `max-file-lines: 900` are the CI limits, not the target.
- Designer-facing: tunables are `@export`s or fields on custom `Resource`s saved as `.tres`. Lists of things
  (waves, tiers, patterns, audio cues) are `Array[SomeResource]` exports — never dict/JSON tables in code.
- Inject dependencies (`@export` refs, `setup(...)`, or child discovery by type). Groups are only a production
  fallback for finding the player; tests always inject.
- Autoloads (`EventBus`, `RunManager`, `SettingsManager`) are referenced only from `src/core/**` and
  `src/game/**`. Components, enemies, weapons, pickups, spawning, arena, ui, vfx never touch them.
  `AudioManager.play(cue, pos)` is allowed anywhere but must be guarded by an exported `AudioCue` (no-op if null).
- Pure logic goes in `RefCounted`/static helpers so unit tests need no scene tree.
- Every stateful node exposes `advance(delta)` / `step(...)`; `_physics_process` only delegates to it.
  No `Timer` nodes or `Time.get_ticks_*` for gameplay timing. Randomness goes through an injected
  `RandomNumberGenerator` (`@export var rng_seed: int = 0`, 0 = random).
- Physics layers (see `src/core/physics_layers.gd`): world, player, player_hurtbox, enemy, enemy_hurtbox,
  enemy_hitbox, pickup, kill_zone.

## Files
- Scenes are hand-written `.tscn` (format=3). Every scene/resource gets a valid `uid://` (13 chars `[a-z0-9]`,
  first char a letter). Scripts get a `.gd.uid` generated by `--import`; commit it.
- Folder per feature under `src/`; tests mirror it under `tests/unit|integration|e2e`.
- Tests extend `GameTest` (`tests/support/game_test.gd`): `make_world()`, `temp_user_path()`, autoload reset,
  SettingsManager redirected to a temp file, mouse mode / tree pause restored. e2e tests boot `main.tscn`
  through `E2EHelpers.boot()` and call `E2EHelpers.release_input()` in `after_each`.
- Spawned enemies live in `Game/EnemyContainer`, their gems in `Game/GemContainer`, daggers in
  `Game/ProjectileContainer`; "is this an enemy" means `SpawnDirector.is_enemy(node)` (has a `died` signal).

## Commits
Conventional commits on `main`: `feat(scope): ...`, `fix`, `test`, `chore`, `refactor`, `tune` (balance .tres
tweaks), `ci`, `docs`. Scopes: core, components, player, weapons, enemies, spawning, pickups, arena, vfx, audio,
ui, persistence, game, e2e.

## Asset generation (local MCP servers)
Missing or broken assets are generated locally via user-scope MCP servers (all verified end-to-end; each has a
README with full tool docs in `~/.claude/mcp-servers/<name>/`). The GPU is an 8GB RTX 4070 — run only ONE heavy
service at a time and stop daemons you no longer need (`forge_stop`, `hunyuan_stop`, `ace_stop`).
- Images / textures / sprites: `forge-image` (`transparent=True` for sprites, `tiling=True` for textures).
- 3D props: `forge-image` reference image → `hunyuan3d` `image_to_3d` (textured GLB; cap density with
  `max_facenum`) → `assets/models/meshes/`. Incorrect meshes: regenerate from a cleaner reference image.
- Mesh animation: `mesh-animate` `animate_mesh` (GLB + motion prompt → baked 16-frame vertex-animation FBX
  + MP4 preview; keep meshes ≲100k verts, `decimate_mesh` drops textures — prefer lower `max_facenum`).
- Character rigging: `mesh-rig` `rig_mesh` (HUMANOID mesh → Mixamo-skeleton FBX, 22 bones / 52 with
  `fingers`, ~25 s, ~3GB VRAM; creatures/props stay on `mesh-animate`). `retarget_bvh` bakes a MoMask BVH
  onto the rig → animated FBX+GLB for Godot; `list_mixamo_animations` browses the ~2,453 local clips
  (opaque hash names; `Standard Run` is named).
- Character motion clips: `text-motion` `generate_motion` ('a person walks in a circle' → 22-joint BVH,
  20 fps, ≤9.8 s; the foot-IK variant is the recommended one, plus MP4 preview; ~11 s warm, 1-2GB VRAM).
  Plain everyday actions only (locomotion strong, combat weak); feed the BVH to `mesh-rig` `retarget_bvh`.
- SFX → `assets/audio/sfx/`: iterate fast with `stable-audio` (small-sfx, ~15 s/take), final take with
  `moss-sfx` (48 kHz, ~50 s/take, needs ~14GB free RAM).
- Music: `ace-music` (full tracks, optional lyrics/vocals; >~3 min tracks return `pending` — collect with
  `fetch_music_task`); `stable-audio` medium for quick ambient beds up to 380 s.
- 3D environments: `worldgen` (detached jobs, poll `world_status`; `mesh=true` for walkable levels — Godot
  import needs the Y-flip + vertex-color material setup shown in `~/WorldGen/godot-viewer/`).
- Generators output WAV; existing audio is OGG. Godot imports both — keep WAV for short SFX, convert long
  music to OGG (`ffmpeg -i in.wav -q:a 6 out.ogg`) to keep the repo small.
